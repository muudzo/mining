Great Dyke, Zimbabwe · Phase 1 · leave-one-tile-out cross-validation

Our mineral model scored 0.841. Tested honestly, it scored 0.228.

Chance was 0.226. The model had learned where it had already looked, not where deposits are. Random cross-validation hid that. Spatial cross-validation exposed it.

So we built the test that caught us and published it. GeoMine audits exploration models for the ways they flatter themselves, and signs the result with a certificate you can re-derive on your own machine.

One command. One exact hash.

The protocol runs on 17 real, named Great Dyke deposits. Run it anywhere and you get the same certificate we publish. The hash covers the protocol version, the model, the data and the quantised scores, so it won't drift between machines.

shell 
git clone https://github.com/muudzo/mining.git && cd mining
pip install -e ".[api,audit]"
geomine audit benchmark/dataset.parquet benchmark/model.joblib --block-size-km 25.0

Five tests. Public thresholds.

  1. Spatial leakage

    Does the score collapse when nearby points can't leak between training and testing? The failure above. Failing it caps the grade at D.

    gap < 0.30

  2. Beats chance

    Is spatial-CV PR-AUC better than picking locations at random?

    > class prior

  3. Bootstrap stability

    Do the model's feature effects hold their direction across resamples?

    ≥ 0.50

  4. Calibration

    When the model says 30%, is it right about 30% of the time?

    ECE < 0.10

  5. Feature–label leakage

    Is any input a disguised copy of the answer? Failing it also caps the grade at D.

    |r| < 0.95

The protocol is open source: geomine/audit/core.py.

Grade A. Which is not praise.

The sample report audits our own benchmark model. It passes all five tests, and the report still says plainly that the model is weak: spatial PR-AUC of 0.144 against a chance level of 0.124.

A grade tells you the number is honest. What the number is worth is a separate question, and the report answers it in plain language.
